Exposure and data safety

SEC

Accounts protect the data; these check the edges around them.

IDPriorityStepsExpected
SEC-01Critical Without signing in, request GET /api/datasets and DELETE /api/datasets/1 with curl. 401 for the first. The second is refused before it reaches the endpoint, and nothing is deleted.
SEC-02Critical With a valid session cookie, POST /api/chat/sessions with curl: once without the X-DataMind-Csrf header, once with Sec-Fetch-Site: cross-site. 403 both times, each naming the reason.
SEC-03High Request /swagger from a published production build. Not served outside development.

SEC-05Medium Upload a CSV with a cell such as =1+1 or <script>alert(1)</script>, then export it. Displayed as text, never rendered as markup. In the exported CSV the =1+1 cell starts with an apostrophe, so a spreadsheet shows it as text.

SEC-07Medium Upload a file larger than 25 MB. Refused with “That upload is too large”, naming the limit.

Filing a defect

HOW

What makes a report actionable here.

IncludeWhy it matters
Case ID and the exact steps Ties the report to a known expectation instead of an impression.
The project and its row count Figures depend entirely on the uploaded file; a bug on 400 rows may not appear on 40,000.
Screenshot, plus the browser console The app catches render failures in an error boundary — the console holds the actual cause.
The API's response Every failure returns ProblemDetails with a title and a detail. Paste both; they usually name the fix.
Which provider was selected Assistant behaviour varies by model, and the built-in planner is the fallback for all of them.
